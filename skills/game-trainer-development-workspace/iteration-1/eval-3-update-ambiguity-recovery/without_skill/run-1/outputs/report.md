## 故障判断与修复门槛

“取第一个”会让地址选择依赖扫描顺序；两个具有相同字节模式的站点可能语义不同。删除 build 校验还会把未知指令布局当作已支持版本。修复采用独立 build profile、语义验证和唯一性门槛。

旧 build 的一次命中只证明该合成输入满足约束；不外推到新 build。新 build 两个有效候选时进入 ambiguous 状态，保持零写入；另一个版本 0 命中进入 unsupported 状态，保持零写入。若两个原始候选中仅一个通过独立验证的语义条件，可选择该唯一有效候选；若仍有两个，需补充实测证据、收紧签名或更新 profile，再重跑全部测试。

## 开发者实施顺序

1. 冻结现有已知可用 profile 和原始字节；新增版本另建 profile。记录产品/模块标识、架构、build ID、文件或规范化代码哈希、模块大小、代码扫描范围、预期指令、目标内存区域约束和补丁范围。profile 来自已审核证据，运行时不得将当前未知模块哈希自动登记为可信版本。本脚本 fixture 自动生成哈希只是构造测试输入。
2. 首次解析前确认 build 与模块身份。未知 build、大小不符或哈希不符直接停止。本脚本对整个合成缓冲区计算 SHA-256；真实 PE 需要明确采用磁盘文件哈希或去除已知重定位的代码哈希，不能直接照搬整个运行时模块哈希。
3. 仅在已知代码区扫描带通配符模式，记录原始候选数；对每个候选验证指令边界、完整指令形式、上下文、操作数类型、RIP 解码目标和目标区域属性。原始候选和过滤后候选都需要留日志。过滤后的数量 0 停止，1 才允许生成租约，大于 1 停止。不要按候选地址排序后选首个。
4. 创建会话租约：进程实例身份（PID 加创建时间或更强的实例标识）、模块加载代次、build/hash、基址、RVA、精确原始字节、预期补丁字节、目标 RVA。这里的 session 字符串代表进程实例与模块代次的组合，而不是 PID。重启、同址重载、PID 复用、build 变化或基址变化都销毁旧租约。持久化 profile 只缓存证据与 RVA 规则，不持久化可继续写入的地址租约。
5. 每次 enable/disable 都先检查当前实例与模块，再比对补丁区字节。ready 状态期望原始字节；enabled 状态期望本工具的补丁字节。相同操作重复调用只在字节仍匹配时返回幂等成功。
6. enable 额外重验完整原指令与上下文。保存精确原始字节，按完整指令范围写入补丁，回读核对后才能标记 enabled。此示例替换一条 7 字节指令，旁边 3 字节上下文保持原状；它仅演示补丁生命周期，不证明 NOP 对真实游戏有正确业务效果。
7. disable 只在当前字节精确等于本工具补丁时恢复该租约保存的原始字节，回读后标记 ready。遇到第三方修改进入 conflict，保留现场字节并记录 expected/actual/build/session/RVA；暂停后续操作，不自动覆盖、不“强制恢复”、不把新读到的字节误当原始字节。人工协调所有权后重新获取可信基线与新租约。新会话即使出现相同 NOP 字节，也不继承旧会话恢复权。
8. 真进程适配层需将身份检查、比较、写入、回读作为受控事务，确保目标线程不会在指令半写时执行，处理页保护、指令缓存刷新、写失败与中途模块卸载。单纯两次读取不保证原子性。本脚本仅模拟串行、稳定字节缓冲区；未模拟真实线程或 OS 写入异常，接入层必须另做故障注入验证。部分写失败只能在确认身份及本事务写入部分仍归本工具所有时处理；否则停止并保留证据。

## 指令与 RIP 解码约定

合成序列：`48 8B 05 dd dd dd dd 48 85 C0`。

前 7 字节为 x64 `mov rax, qword ptr [rip + disp32]`，后 3 字节为 `test rax, rax`。仅 disp32 通配；不是通用反汇编器。disp32 按小端、有符号 int32 解码：

```text
next_instruction_va = module_base + instruction_rva + 7
referenced_va       = next_instruction_va + signed_disp32
referenced_rva      = instruction_rva + 7 + signed_disp32
```

在正位移测试中 RVA=32，disp32=121，目标 RVA=160；base=0x140000000，目标 VA=0x1400000A0。负位移测试在 RVA=96，disp32=-71，目标 RVA=32，验证了符号扩展。此结果是内存操作数引用地址；不是读取该地址后得到的指针值。

脚本代码扫描区为 [16,112)，目标区为 [128,192)，目标访问宽度为 8 字节；因此允许的目标起始 RVA 是 [128,184]。真实模块需要再验证代码/数据节属性、访问宽度、可读性、目标对象语义与上下文指令，不能用“地址落在模块里”代替语义证据。真实签名必须来自可信指令边界；该合成示例的逐字节扫描不证明真实可变长指令边界。

## 离线覆盖矩阵

| 行为 | 实测断言 |
|---|---|
| 旧 build 唯一命中 | 选择 RVA 32，解码目标 RVA 160 |
| 另一版本 0 命中 | candidate_count:0;raw:0；整个缓冲区保持一致 |
| 新 build 多候选 | candidate_count:2;raw:2；整个缓冲区保持一致 |
| 两候选语义过滤 | 目标 RVA 240 被排除，RVA 32 唯一有效 |
| 全部目标不合法 | candidate_count:0;raw:1 |
| build/哈希失配 | build_mismatch / image_hash_mismatch |
| RIP 正负位移及指令形式 | 正负目标正确，变更 opcode 或越界均报错 |
| enable/disable 与幂等 | NOP 精确写入；恢复后全缓冲区等于最初快照 |
| enable 前被改动 | byte_conflict；零写入 |
| disable 前被第三方改动 | byte_conflict；第三方字节保留；后续操作被冻结 |
| 同地址新会话 | enable 与 disable 均 stale_session；零写入 |
| 模块重定位/build 变化 | 旧租约失效 |
| 新会话新解析 | 新基址重新解析后启用、恢复成功 |
| 补丁范围外上下文变化 | unexpected_instruction；零写入 |
