# 首轮结果解读

这轮检查技能能否组织可复查的调查、定位和恢复验证，不把离线模型结果换算为真实游戏开发成功率。每题每配置一次，共六次执行；没有重复采样估计随机波动。

## 已观察到的方法差异

- 原版机制：两组均实际调用现有 ILSpy 导出原版类型，核对当前源码与样本关系，而非只依赖注释。使用技能组映射五类，基线映射四类；后者仍能完成主要机制判断。哈希不符只标记未验证、窗口 Z 序恢复不是游戏补丁、原版来源范围等事实以代码为准。
- 第二案例：两组均独立扫描 AOB，解码字段 displacement 与有符号 RIP displacement，扫描三帧变化和指针槽，推导两 build 的根、链与字段。使用技能组增加镜像哈希校验、逐字节扫描与发现后单独核对真值；基线以 4/8 字节对齐为明确假设。独立评分者毒化 manifest 的答案字段后重算，两组结果保持一致。
- 更新恢复：两组均编写并实际运行字节模型，覆盖零命中、多候选、RIP 解码、旧会话、启停与恢复冲突。使用技能组模型细分 PID/start/base/build/epoch，并增加短写回滚等场景；基线的会话标识更简化。测试数不同不代表质量按数量线性增长，应看风险场景是否被执行断言覆盖。

## 如何看通过率

两组都能完成的断言对区分技能增益帮助有限。通过率主要表明本轮产物达到所设基础要求；若两组得分相同，不应写成技能提高成功率或节省成本。未把代理完成事件未提供的耗时、token、工具调用总数估成数字；脚本运行毫秒数也不是开发耗时。

对照组使用相同任务与公开输入，仍可使用现有通用技能和本机工具。新技能组另读主流程与参考资料。这是具有较强基线的流程对照，不是完全无指导的人类新手实验，也不是模型能力排名。

## 当前覆盖缺口

1. 第二案例生成器、协议与示例布局公开。定位器确实用字节而不是答案表发现地址，但该实验不是未知游戏或隐藏 oracle 的盲测。
2. 两 build 各两 session 和三帧变化是文件模型；没有真实进程句柄、VirtualQueryEx/ReadProcessMemory、并发读取、权限变化、游戏加载或内存页生命周期。
3. 第二案例实际 RIP 目标主要在正向范围。更强验证应让负位移也贯穿整条候选发现与核对流程，不能以公式写对代替所有路径测试。
4. fixture 自检和补丁模型是共同验证器的能力，不能全部归为各自定位器实现的功能。独立评分应分别看 resolver 与共同工具的证据。
5. 首版 Mono、IL2CPP、Unreal 为带验证要求的路线文档，未在对应真实游戏中执行。跨实际会话与新机器交付仍待开展。
6. 源码摘录中的仓库链接在独立安装包外可能无对应项目；技能主流程和离线实验保持自包含，案例链接用于回到本仓库复查。

## 下一轮最有价值的验证

选择另一款可运行游戏的一个最小功能，先建立受控动作与负面对照，再重复重启、换局、关闭恢复。若先改进离线评估，使用未公开参数的随机布局、正负 RIP、非对齐字段、多候选均语义有效、损坏镜像与输入哈希失配，冻结旧技能后再运行新旧版本对照。

本轮先交付可使用的 v0.1.0 评审版。评审页面用于核对输出是否实用、证据是否足够和报告是否冗长；不为刷高评分加入游戏特例或答案偏移。
