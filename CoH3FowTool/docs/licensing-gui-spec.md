# GUI 与授权最终规格（待整体确认）

整理日期：2026-11-09。本文汇总用户逐轮确认的选择；确认本文后进入实现。本文件是设计规格，不代表授权系统或 GUI 已完成。

## 1. 产品基线与发行

- 以用户亲测的 `启动(管理员).bat` 当前选中的 `publish/CoH3FowTool.exe` 为功能基线。
- 基线版本为 `2.0.0.0`，大小 `36,485,520` 字节，SHA256 为 `61C62243BFF6D0D9CD4004FB04721D8BD9BC07E794E81F389A1A7A820B78422F`。
- 沿用该版本已有的开启、关闭、状态与还原能力；实验探针不作为发行基线。
- 发行物是 Windows x64 中文图形界面、自包含单 EXE，用户电脑无需另装 .NET。
- 双击 EXE 时通过正常 Windows UAC 请求管理员权限，用户端不再依赖管理员批处理。
- 界面提供游戏路径选择、运行状态、开启、关闭、还原及授权信息；不同安装路径应可选择。
- 游戏版本校验、既有功能和游戏运行前提继续适用。GUI 与授权改造本身不构成新的联机兼容性验证。

## 2. 兑换与本机限制

- 用户只输入授权码，不注册账号、不手填机器码、不绑定 IP。
- 首次成功激活必须联网；服务端记录兑换及设备绑定关系，之后该码失去在其他设备再次兑换的资格。
- 本机保存已签名、绑定设备的许可证。复制程序或许可证到其他电脑后，应因设备不匹配而验证失败。
- 兑换成功与绑定关系必须一致；并发兑换只有一个设备成功。同机网络重试应能取得已有激活结果，避免成功后丢失响应造成授权损失。
- 设备识别在后台完成。重装或硬件变化引起的授权恢复由管理员处理，具体稳定性需通过实现验证。

## 3. 永久授权

- 只在首次激活时联网，之后仅本机验证许可证，不安排定期联网或七天刷新。
- 已签发的永久许可证长期有效；后续云端停用不传播到不再联网的旧电脑。
- 永久授权不承诺远程撤回或强制旧设备失效。换电脑时，由管理员决定是否另发新授权；新授权不等于旧电脑上的永久许可证作废。

## 4. 限时授权

- 支持指定使用天数，从首次成功激活时开始计时；到期时间以服务端记录为准。
- 每次启动 GUI 都联网校验现有授权与设备关系，不重新消耗激活码。
- 启动校验连接失败、授权到期或被停用时，仅保留状态查看、关闭及还原。
- 正常运行期间按已确认的到期时间检查；不安排运行中的定时联网，不使用七天离线缓存。
- 管理员修改的停用等状态在下次联网校验时生效，不承诺即时传播到正在运行且未联网校验的客户端。
- 到期或授权异常时阻止新的开启动作，并保留关闭、还原与状态查看。

## 5. 管理与授权服务

- 用户端、管理员专用管理端、常在线云端授权服务三个部分分离；用户只收到用户端 EXE。
- 管理端供所有者发码、选择永久或限时授权、查看兑换和设备状态，以及进行相应管理。
- 优先评估和复用成熟、具有公开文档的授权框架，再集成所需界面与一次兑换规则。
- 用户端不内置签名私钥、管理员凭据或管理级 API 密钥；签名与管理权限留在可信服务端。
- 具体框架、部署位置与实际运行费用在实现评估后明确；本文不授权购买服务或对外部署。

## 6. 代码保护与简化范围

- 代码保护目标是提高逆向和修改成本；不把“任何人都逆不出”作为验收承诺。
- 给用户的发行物不附源代码、调试符号、管理端或服务端密钥。
- 不增加账号注册、商城、支付或自动售码流程；由管理员直接发放授权码。
- 单 EXE 是用户端发行形式；授权服务独立运行，不要求所有者的个人电脑一直开机。

## 7. 验收要点

1. GUI 能保留基线的既有功能，正常请求 UAC；自包含 EXE 的独立运行与路径选择通过验证。
2. 一个未兑换码首次成功后，其他设备使用同一码失败；复制本机许可证到其他设备也失败。
3. 并发兑换和同机重试行为符合第 2 节，不出现重复发放或成功后授权丢失。
4. 永久授权激活后断网重启可用，后续启动没有周期性授权联网要求。
5. 限时授权从首次成功激活起算；每次启动核验，到期或连接失败时保留关闭、还原和查看状态。
6. 用户发行物不携带源码、签名私钥或管理员凭据。
7. 第二台电脑的实际验证与本机隔离测试分开记录；未实测的项目明确标注，不将字节自检当作画面或跨机验收。
