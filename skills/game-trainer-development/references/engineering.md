# 工程实现与更新适配

## 工具与实现选择

先检查现有工程、目标位宽和已安装工具。记录实际版本、一次最小调用及能力缺口，再选实现语言。

| 条件 | 候选 | 先验证 |
|---|---|---|
| 现有 WinForms/.NET 工程、外部读写 | C# + 小型 Win32 适配层 | x64/PInvoke 类型、精确读取、目标运行时依赖 |
| 原生模块、指令级集成 | C++ | 编译器/SDK、ABI、生命周期、构建可复现 |
| CE 探索或受控原型 | CE Lua/AA | CE/扩展版本、API 实际名称、关闭恢复 |
| Mono 或引擎有可维护扩展接口 | 引擎支持的插件/脚本 | 目标版本、加载机制、运行时类型 |
| 离线数据/文件功能 | 文件解析/转换工具 | 格式 round-trip、备份及版本 |

不同语言可以共享数据契约，不要先搭多语言框架。调试器/CE/MCP/REA 的安装、服务连接、运行时附加分别验证。

## 最小架构与状态机

Session（PID/startTime/module/build/epoch）→ Resolver → ValidatedSnapshot → FeatureController → Presentation。

- Session 负责句柄和取消；Resolver 只产出带 build/epoch 的候选；使用前再次核验。
- Snapshot 包含采样时间和有效性，避免 UI 使用一半新一半旧的数据。
- Controller 状态建议 detached / resolving / ready / enabled / faulted。版本失配和短读进入诊断状态，停止写入、撤下陈旧标记。
- UI 开关表达期望状态，实际状态由 Controller 回报；避免界面亮起而底层尚未生效。
- 构建第一条完整路径后再抽象公共引擎。测试可读写适配层，用 fake adapter 覆盖短读与会话变更。

## 指针、AOB 与结构

记录 module 名、SHA256、RVA、pointer width、每级 dereference/offset、field type 与合法范围。明确末级是加偏移还是继续解引用。

AOB 先按可执行区域或目标段筛选；通配重定位、地址和不稳定位移，核验匹配上下文。若匹配形如 `mov reg,[rip+disp32]`，按指令末尾地址加有符号 disp32 计算目标，不把操作数当绝对地址。

0 匹配：检查 build/段/扫描范围，报告失配；多匹配：对每个候选验证指令目标、对象不变量及行为；唯一匹配：继续语义验证。签名唯一性不是功能正确性的替代。

对象定位需要把显示缓存、模拟状态、派生值、共享对象分开。受控改变目标时同时观察同值 decoy；重启和换场景再取证。

## 写入事务与恢复

实现顺序是识别目标→核验当前状态→保存快照→执行→读回→登记所有权→功能验证。

字段值可能由游戏持续计算；保存旧值不意味着退出时仍应写回。明确“锁定数值”“一次性设置”“修改上限”等语义。指令字节则按已知补丁严格比对恢复。

补丁记录包含 build、模块/RVA、原始字节、安装字节、资源及所有者、启用 epoch。启用前核对原字节；重复启用只有当前字节等于自己安装的字节才幂等。失败时回滚本次已完成步骤，并保存无法回滚的冲突证据。

禁用前比较当前字节与本补丁：相同才恢复；不同则记 conflict，避免覆盖别的组件或新版本。处理完整指令、跳转范围、RIP-relative 重定位、栈对齐、callee-saved 寄存器和 flags 的语义。分配区释放前证明不再有线程执行或引用它。离线模型仅能验证协议逻辑。

## 生命周期测试矩阵

| 场景 | 读取/覆盖层 | 写入/补丁 |
|---|---|---|
| 新进程/ASLR | 重新取基址与根，不复用旧地址 | 清除旧所有权，重新校验 |
| 换局/存读档 | epoch 失效、取消扫描、隐藏旧数据 | 旧对象禁止写入 |
| 短读/无权限/退出 | 明确 fault、释放句柄 | 停止操作，记录可恢复情况 |
| 重复开关 | UI 与真实状态一致 | 幂等、原字节恢复 |
| 外部状态变更 | 重验候选 | 恢复冲突不覆盖 |
| 更新 build | 重建定位证据 | 旧补丁禁用，重新验证 |
| 分辨率/DPI/窗口模式 | 坐标与点击穿透测试 | 按实际 UI 路线测试 |

每项记录测试输入与实际观测，未执行为 not_run。出现实际失败时保留原始日志与最小复现，不通过更改报告来掩盖。

## 每 build 的可维护产物

建议在开发区存 `builds/<hash>/`，包含身份清单、offsets/signatures、布局说明、证据和回归结果；避免存绝对运行地址作为永久根。日志使用地址/build/epoch 关联，但不落账号凭据。

新 build 恢复顺序：文件身份→模块/引擎变化→签名0/1/多命中→结构差异→受控行为→重复会话→打包。不要为了匹配新版本随意扩大通配范围；保留旧版兼容性测试。

## 发布模块

技术成果先可独立运行，商业功能按需接入。客户包只含运行文件、配置和使用说明；维护包可含源码映射、符号和验证工具。生成清单与 hash，测试从解压目录启动。包中不带私钥、授权数据库、开发环境绝对路径或调试凭据。

本仓库接入 LicensingSystem 时读其当前规则和入口；保留 ProductId 隔离、签名验证和公钥绑定，构建顺序按根规则。未请求商业集成时不改授权服务或发卡。只修改本次新工程，不重建既有客户包。
