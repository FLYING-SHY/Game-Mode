## 故障原因与方案变化

旧输入实现中 x64 `INPUT` 只有 32 字节，原生 ABI 要求 40 字节；实际 `SendInput` 返回 0，Win32 错误 87，旧版却忽略返回值并提示成功。另有把回车作为 Unicode 字符发送、中文输入法截获物理键的问题。修复后的真实 Win32 窗口集成测试收到了完整 `cheat_revealall`、一次 Ctrl+Shift+Grave 和一次物理回车。

当前游戏无 `-dev` 时主菜单控制台热键实测可用，对局内热键仍未打开控制台。旧 PCMD 路径的五处补丁写入成功，也没有证明后续命令满足 sim 校验。`0x33A1C68` 除 CRC 还会写 `BasicFogOfWarModule` 玩家揭示标志，先前“纯 CRC、UI 事件才负责揭雾”的结论错误。

2.0 默认改为六处本地显示分支与四个显示开关；`reveal` / `hide` 均不依赖控制台输入，不发送 PCMD，也不应用旧遥测改写。

## 构建与单文件自检

最终自包含程序发布成功。仅复制单个 exe 到独立目录，设置 `DOTNET_ROOT` / `DOTNET_ROOT_X64` 为不存在的共享运行时目录，设置 `DOTNET_MULTILEVEL_LOOKUP=0`、`DOTNET_ROLL_FORWARD=Disable` 后运行 `selftest`，退出码 0，六项全部通过：

1. 原版六处补丁点均能唯一定位，目标为原始状态。
2. 在临时游戏文件副本上 `file-apply` 成功。
3. 临时副本六处均为已补状态。
4. 目标字节与预期补丁一致。
5. 临时副本 `file-revert` 成功。
6. 还原后临时副本与原 exe 字节完全一致。

该自检没有写入实际游戏文件。自检输出位于发行包根目录 `selftest.log`。

独立反汇编检查也已更新为 2.0 的六处显示分支：[检查脚本](<verify_patches.py>) / [检查输出](<verify_display_2_0.log>)，结果为 `ALL OK`。这项只证明定位、字节及跳转改写，不单独证明画面效果。
